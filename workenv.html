סביבת העבודה

כל תרגילי הבית נכתבים ב-C על Linux ונבדקים אוטומטית. הפרק הזה הוא ארגז הכלים: VM, טרמינל, פקודות, הפניות והרשאות.

הבדיקה אוטומטית. מבנה תיקיות, שמות קבצים ואריזה ב-tar חייבים להיות בדיוק לפי ההנחיות – אחרת הסקריפט נכשל ומאבדים נקודות גם אם הקוד נכון, ואין ערעורים. יש סקריפט "בדיקת הגשה" – אחריותכם להריץ אותו.

לפי נתוני הקורס, הממוצע של מי שתרגל בחנים גבוה ב-12 נקודות; לציון 70 הפער הוא 29 נקודות.

מכונה וירטואלית: Vagrant + Ubuntu

VM היא אמולציה של מחשב שלם, שמאפשרת להריץ מערכת הפעלה אחרת (Linux על Windows, למשל). בקורס נכתוב קוד "רגיש" שעלול לשבש מערכת, אז ה-VM גם מגינה על המחשב האישי.

  • VirtualBox (ב-Windows ובאינטל) או QEMU (במעבדי אפל): VMM – Virtual Machine Monitor חינמי וקוד-פתוח, התוכנה שמריצה את המכונה.
  • Vagrant: כלי קוד-פתוח שמפשט יצירת VM, התקנת מערכת ההפעלה והעבודה מולה. הכל משורת הפקודה.

איזה מחשב יש לי?

ההתקנה שונה לפי סוג המעבד. בודקים בתפריט התפוח ← About This Mac (אודות המק): אם בשורה Chip כתוב Apple M1/M2/M3/M4, זה מעבד אפל. אפשר גם בטרמינל: uname -m מחזיר arm64 במעבד אפל ו-x86_64 באינטל.

Mac עם מעבד אפל

במעבדי אפל VirtualBox לא מתאים, ובמקומו משתמשים ב-QEMU. מערכת ההפעלה ב-VM היא Ubuntu 22.04 לארכיטקטורת ARM.

לפני הכל: שיתוף קבצים. התיקייה המסונכרנת /vagrant עובדת דרך שיתוף קבצים של ה-Mac, אז מפעילים אותו פעם אחת:

  1. System Settings (הגדרות המערכת) ← General (כללי) ← Sharing (שיתוף).
  2. מפעילים את File Sharing (שיתוף קבצים), כך שהמתג ירוק.
  3. לוחצים על כפתור המידע (ⓘ) מימין ל-File Sharing, ואז על Options… (אפשרויות).
  4. מוודאים שמסומן Share files and folders using SMB.
  5. תחת Windows File Sharing, מסמנים את המשתמש שלכם. המערכת תבקש את סיסמת ה-Mac, וזה הכרחי.
  6. Done וסוגרים את ההגדרות.

יצירת ה-VM: יוצרים תיקייה חדשה וריקה, ופותחים בה טרמינל: ב-Finder, קליק ימני על הנתיב בתחתית החלון ← New Terminal at Folder. ההתקנה משתמשת ב-Homebrew; אם הטרמינל עונה brew: command not found, מתקינים אותו קודם לפי ההוראה בעמוד הראשי של brew.sh.

# once per computer:
brew install qemu
brew install --cask vagrant
vagrant plugin install vagrant-qemu

# in the new, empty folder: create the Vagrantfile
cat <<EOF > Vagrantfile
Vagrant.configure("2") do |config|
  config.vm.box = "perk/ubuntu-2204-arm64"
  config.vm.synced_folder ".", "/vagrant"
  config.vm.provider "qemu" do |qe|
    qe.ssh_port = "50022" # change ssh port as needed
  end
end
EOF

vagrant up --provider=qemu   # create the VM and install the OS
vagrant ssh                  # connect to the VM

את שלוש הפקודות הראשונות מריצים פעם אחת במחשב. ל-VM נוסף, בתיקייה חדשה, מספיק ה-Vagrantfile ו-vagrant up. אם רוצים שני VM שרצים יחד, צריך לתת לשני ssh_port אחר.

Windows ומחשבי אינטל

מורידים ומתקינים את VirtualBox ואת Vagrant, יוצרים תיקייה חדשה וריקה ופותחים בה טרמינל. ב-Windows: מחזיקים SHIFT, קליק ימני בתיקייה ← Open in Terminal. ה-SHIFT חשוב, כדי שהטרמינל ייפתח עם ההרשאות המתאימות.

vagrant init hashicorp/bionic64
vagrant up          # create the VM and install the OS
vagrant ssh         # connect to the VM

בשני המקרים: הגדרה ראשונה בתוך ה-VM

אחרי שה-VM עלה (בפעם הראשונה זה לוקח זמן) ונכנסתם עם vagrant ssh:

sudo apt update -y
sudo apt upgrade -y
sudo apt install gcc build-essential -y
sudo apt clean && sudo apt autoremove -y
exit
vagrant reload      # restart the VM (on the host), then vagrant ssh again

vagrant reload שימושי גם בכל פעם שמשהו ב-VM מתנהג מוזר.

רק VM

עבודה עם WSL, עם אמולטור, או ישירות על ה-Mac או על Linux – לא תעבוד כמו שצריך, ועלולה להזיק. התרגילים נבדקים בסביבה של ההנחיות האלה בלבד, וערעור על קוד דורש צילום מסך מתוך ה-VM.

פקודות, סקריפט או C?

בקורס כותבים בשלוש "שפות", והן לא מתחרות – כל אחת היא שכבה מעל הקודמת. ה-shell עצמו הוא תוכנית C: כשמקלידים ls -la, bash קורא את השורה, מפצל אותה למילים, ומריץ את ls עם fork, exec ו-wait (פרק 3).

כלל אצבע

אם המשימה היא "תעשה את הפעולות האלה על קבצים" – זה סקריפט: כל שורה היא פקודה שאפשר היה להקליד ידנית. אם המשימה היא "תממש את ההתנהגות של מערכת ההפעלה" – ליצור תהליכים, להריץ תוכניות, לחכות, לאסוף זומבים – זה C עם קריאות מערכת. תרגיל שבו כותבים shell ב-C הוא בדיוק המקרה השני: בונים בעצמכם את מה ש-bash עושה בשבילכם בחלק הראשון.

סקריפטים: מה שצריך לדעת

סקריפט הוא קובץ עם רצף פקודות, בדיוק כמו בשורת הפקודה. סיומת מקובלת (לא חובה): .sh. השורה הראשונה מציינת את המפרש, ואז נותנים הרשאת ריצה. כל הדוגמאות כאן הורצו, והפלט שמוצג הוא הפלט האמיתי.

ארגומנטים

#!/bin/bash
echo "script: $0"
echo "first:  $1"
echo "second: $2"
echo "count:  $#"
$ chmod +x args.sh
$ ./args.sh hello "two words" 3
script: ./args.sh
first:  hello
second: two words
count:  3
סימןמשמעות
$0שם הסקריפט כפי שהורץ
$1 … $9הארגומנטים לפי הסדר. ארגומנט שלא נשלח הוא מחרוזת ריקה, לא שגיאה
$#מספר הארגומנטים (בלי $0)
"$@"כל הארגומנטים, כל אחד בנפרד

"two words" הוא ארגומנט אחד: המרכאות קובעות איפה מילה מתחילה ונגמרת, וה-shell מוריד אותן לפני שהוא מעביר את הארגומנט.

מרכאות: למה תמיד "$1"

אחרי שמשתנה מוחלף בערך שלו, bash מפצל את התוצאה לפי רווחים. בלי מרכאות, ערך עם רווח הופך לשני ארגומנטים:

name="My Docs"
mkdir $name      # two folders: My, Docs
mkdir "$name"    # one folder: My Docs
כתיבהמה יוצא
echo "home: $HOME"מרכאות כפולות: משתנים מוחלפים. home: /home/vagrant
echo 'home: $HOME'מרכאות בודדות: הכל מילולי. home: $HOME

החלפת פקודה: $(...)

$(פקודה) מריץ את הפקודה ושם את הפלט שלה במקומו. כך מכניסים תוצאה של פקודה לתוך שורה אחרת:

echo "today is $(date +%A)"
lines=$(wc -l < notes.txt)          # save the output in a variable (no spaces around =)
echo "$(basename /home/vagrant/src/main.c)"   # main.c
echo "$(dirname /home/vagrant/src/main.c)"    # /home/vagrant/src

basename משאיר רק את שם הקובץ מתוך נתיב מלא, ו-dirname את התיקייה שלו. שימושי כשמקבלים נתיב מלא כארגומנט ורוצים את השם בלבד, למשל כדי ליצור קובץ באותו שם במקום אחר.

נתיבים בסקריפט

  • הסקריפט רץ בתיקיית העבודה של מי שהריץ אותו, לא בתיקייה שבה הוא שמור. mkdir out ייצור את out איפה שהמשתמש עומד.
  • cd בתוך סקריפט משנה את התיקייה רק לסקריפט. כשהוא מסתיים, הטרמינל נשאר איפה שהיה.
  • אחרי cd, נתיב יחסי שקיבלתם כארגומנט כבר לא מצביע לאותו מקום. לכן עובדים עם נתיבים מלאים, או כותבים את היעד במפורש: "$1/file.txt" במקום cd "$1" ואז file.txt.

קוד יציאה ושרשור

כל פקודה מחזירה מספר: 0 = הצליחה, כל דבר אחר = נכשלה. הקוד של הפקודה האחרונה נמצא ב-$?:

$ ls nofile; echo "exit code: $?"
ls: cannot access 'nofile': No such file or directory
exit code: 2
$ ls / > /dev/null; echo "exit code: $?"
exit code: 0

על זה בנוי &&: gcc p.c -Wall -o p && ./p מריץ את התוכנית רק אם הקומפילציה הצליחה. גם תוכנית C מחזירה קוד כזה – הערך שהיא מחזירה מ-main.

ירידות שורה: LF ולא CRLF

ב-Windows כל שורה נגמרת בשני תווים (CRLF, \r\n), וב-Linux בתו אחד (LF, \n). סקריפט שנכתב ב-Windows נראה תקין בעורך, אבל ה-\r הנסתר נדבק לכל שורה. בשורה הראשונה המפרש נעשה /bin/bash\r, שלא קיים, וההרצה נכשלת בהודעה מבלבלת:

$ ./script.sh
bash: ./script.sh: /bin/bash^M: bad interpreter: No such file or directory

ה-^M הוא ה-\r. בגרסאות חדשות של bash ההודעה קצרה יותר: ./script.sh: cannot execute: required file not found. התיקון:

  • ב-VSCode: ללחוץ על CRLF בפינה הימנית התחתונה ולבחור LF. ב-Notepad++: Edit → EOL Conversion → Unix (LF).
  • מתוך ה-VM, בלי עורך: sed -i 's/\r$//' script.sh

אותה בעיה קיימת גם בקבצי C ובקבצי קלט לבדיקות, אבל שם היא שקטה יותר: התו \r נכנס לנתונים בלי הודעת שגיאה.

דיבוג: bash -x

מריץ את הסקריפט ומדפיס כל פקודה, אחרי שכל המשתנים כבר הוחלפו, לפני שהיא רצה. כך רואים בדיוק מה הסקריפט עשה:

$ bash -x ./lines.sh /tmp/notes.txt /tmp/out
++ wc -l
+ n=3
++ basename /tmp/notes.txt
+ echo 'notes.txt: 3 lines'
+ cat /tmp/out/summary.txt
notes.txt: 3 lines
תרגיל: סיכום שורות

כתבו סקריפט lines.sh שמקבל נתיב מלא לקובץ ונתיב לתיקייה קיימת, וכותב לתוך summary.txt בתיקייה שורה אחת בפורמט <file name>: <N> lines (שם הקובץ בלבד, בלי התיקיות). אחר כך הסקריפט מדפיס את הקובץ שנוצר.

פתרון 
#!/bin/bash
n=$(wc -l < "$1")
echo "$(basename "$1"): $n lines" > "$2/summary.txt"
cat "$2/summary.txt"

wc -l < "$1" (עם הפניית קלט) מדפיס רק את המספר. wc -l "$1" היה מדפיס גם את שם הקובץ. בדקתי בהרצה על קובץ בן 3 שורות: הפלט notes.txt: 3 lines.

הרשאות

לכל משתמש יש שם, והוא שייך לקבוצה אחת או יותר (הפקודה id מציגה). sudo מריץ פקודה כ-superuser. לכל קובץ יש בעלים וקבוצה, ו-3 הרשאות לכל אחד מ-3 סוגי משתמשים:

תרגיל: סקריפט עם nano

תרגול נוסף (שקף 25)

כתבו סקריפט ש:

  1. יוצר תיקייה חדשה בתיקיית המשתמש, ששמה הוא הארגומנט הראשון.
  2. מעתיק אליה קובץ C מהתיקייה המסונכרנת /vagrant.
  3. מקמפל אותו לקובץ ריצה באותה תיקייה.
  4. נותן לקובץ הריצה את כל ההרשאות למשתמש ומבטל את כל השאר.
  5. מדפיס את תוכן התיקייה המלא (-la).
  6. מריץ את התוכנית עם הפניית פלט לקובץ בתיקיית המשתמש.
  7. מוחק את התיקייה וכל תוכנה בפקודה אחת – רק אם ההרצה הצליחה.
פתרון 
#!/bin/bash
mkdir ~/"$1" && \
cp /vagrant/hello.c ~/"$1"/ && \
gcc ~/"$1"/hello.c -Wall -o ~/"$1"/hello && \
chmod 700 ~/"$1"/hello && \
ls -la ~/"$1" && \
~/"$1"/hello > ~/output.out && rm -r ~/"$1"

הנקודה החשובה היא && לפני rm -r: המחיקה קורית רק אם התוכנית החזירה 0. בדקתי את הסקריפט בהרצה אמיתית, עם תיקייה מדומה שהחליפה את /vagrant. התוצאה: hello נוצר עם -rwx------, הפלט נכתב ל-~/output.out, והתיקייה נמחקה.

הפתרון שמופיע בקורס: ex01.sh 
#!/bin/bash

mkdir ~/$1
cp /vagrant/test.c ~/$1/
gcc -Wall ~/$1/test.c -o ~/$1/test
chmod u+rwx ~/$1/test
chmod o-rwx ~/$1/test
ls -la ~/$1
~/$1/test 5 > ~/test.out && rm -rf ~/$1

ההבדלים מהפתרון שלמעלה: כאן כל צעד בשורה נפרדת, ורק המחיקה בסוף תלויה בהצלחה (&&), כלומר צעד שנכשל באמצע לא עוצר את השאר. ההרשאות נקבעות בשתי פקודות: הוספה לבעלים והסרה מ-others, בלי לגעת בקבוצה – בעוד ש-chmod 700 מסיר גם את הרשאות הקבוצה. ו-$1 כתוב בלי מרכאות, אז שם תיקייה עם רווח יישבר (מרכאות).

בדיקה מול פתרון לדוגמה והגשה

לתרגילים מצורף לפעמים פתרון מקומפל, ודרכו בודקים שהפלט שלכם זהה תו-לתו. כל הפקודות כאן רצות בתוך ה-VM.

1 · איזה קובץ ריצה מתאים לכם

קובץ ריצה מקומפל למעבד מסוים. ב-VM על מעבד אפל רץ Linux של ARM, וב-Windows ואינטל של x86. בודקים מתוך ה-VM:

uname -m מחזירמשתמשים בקובץ
aarch64הגרסה עם _aarch64 בשם (מעבד אפל)
x86_64הגרסה הרגילה

קובץ שהגיע מבחוץ (דרך /vagrant) מגיע בלי הרשאת ריצה, אז קודם chmod +x. שתי ההודעות שתראו אם משהו לא בסדר:

הודעהפירוש
Permission deniedחסרה הרשאת ריצה: chmod +x ./prog
cannot execute binary file: Exec format errorהקובץ מקומפל למעבד אחר. לקחת את הגרסה השנייה. file ./prog מראה לאיזה מעבד הוא מיועד

2 · אותו קלט, השוואת פלטים

כותבים קובץ קלט עם כמה מקרי בדיקה, ומריצים עליו את שתי התוכניות עם הפניות (פרק 6). הקלט מקובץ גם מדמה סוף קלט (EOF) בדיוק כמו Ctrl+D, כשהקובץ נגמר.

./ref  < tests.txt > expected.txt   # the provided solution
./mine < tests.txt > actual.txt     # your program
diff expected.txt actual.txt

אין פלט מ-diff = הקבצים זהים. אם יש הבדל, diff מראה איפה. למשל, כששורה 2 שונה:

2c2
< b
---
> B

< היא השורה בקובץ הראשון ו-> בשני. הבדלים שלא רואים בעין, כמו רווח בסוף שורה, ירידת שורה חסרה בסוף או \r מ-Windows, נתפסים כאן.

תהליכים ברקע

כשתוכנית מריצה תהליכים במקביל, סדר השורות יכול להשתנות בין ריצות, גם של אותה תוכנית בדיוק. במקרה כזה diff יראה הבדל בסדר, וזה תקין. מה שבודקים הוא שאותן שורות מופיעות.

3 · קומפילציה כמו בבדיקה

הבודק מקמפל עם gcc <files> -Wall -o <exe>. מקמפלים בדיוק כך, ומוודאים שאין אף אזהרה. אזהרה היא לא רק עניין של ניקיון: היא בדרך כלל מצביעה על באג אמיתי, כמו משתנה שלא אותחל או פונקציה בלי #include.

4 · אריזה ובדיקת הגשה

הקבצים צריכים להיות ישירות בתוך הארכיון, בלי תיקייה מסביבם. לכן מריצים את tar מתוך התיקייה שבה הקבצים נמצאים, עם שמות הקבצים בלבד:

tar czf 123456789.tar.gz file1.sh file2.c file3.pdf   # create (c), gzip (z), file name (f)
tar tzf 123456789.tar.gz                             # list what is inside (t)
פקודהמה בפנים
tar czf x.tar.gz a.sh b.c c.pdfa.sh, b.c, c.pdf – נכון
tar czf x.tar.gz myfoldermyfolder/, myfolder/a.sh … – תיקייה בפנים, הבדיקה תיכשל

אחר כך מריצים את סקריפט בדיקת ההגשה שמצורף לתרגיל (python3 <script>.py <file>.tar.gz) ומעתיקים את הארכיון החוצה דרך /vagrant, שמסונכרנת עם התיקייה של ה-VM במחשב.
