Chapter 1 · Introduction

מבוא למערכות הפעלה

הפרק שמסדר את כל המפה: שלושת הנושאים של הקורס, ומה הקרנל בעצם עושה. כמעט כל שאלה במבחן נשענת על המושגים כאן.

מהי מערכת הפעלה

מערכת הפעלה היא שכבת ביניים בין תוכניות המשתמש לחומרה. היא עושה שני דברים: מפשטת (abstraction) את החומרה ומנהלת את המשאבים שלה – המעבד, הזיכרון הראשי, והתקני הקלט/פלט (דיסק, רשת, מקלדת, עכבר, מסך).

מה קורה כשתוכנית רצה

המעבד עובד לפי מודל Von Neumann: בלולאה אינסופית הוא מביא פקודה מהזיכרון, מפענח אותה, מבצע אותה ועובר לפקודה הבאה. גם קוד התוכנית עצמו יושב בזיכרון.

שלושת החלקים (Three Easy Pieces)

הקורס בנוי לפי הספר Operating Systems: Three Easy Pieces (ostep.org), וזה בדיוק שלושת הנושאים שלו:

וירטואליזציה של המעבד

התוכנית cpu.c מסתובבת שנייה ומדפיסה את הארגומנט שלה, לנצח:

int main(int argc, char *argv[]) {
    while (1) {
        Spin(1);              // busy-loop for 1 second
        printf("%s\n", argv[1]);
    }
}

מריצים ארבעה עותקים ברקע עם מעבד אחד בלבד:

האשליה

מעבד פיזי אחד נראה כמו אינסוף מעבדים וירטואליים. מתחת למכסה המנוע מערכת ההפעלה מחליפה בין התהליכים מהר מאוד – זה נקרא Context Switch, ונראה אותו לעומק בפרק 3.

וירטואליזציה של הזיכרון

זיכרון פיזי (RAM) הוא מערך של בתים: קריאה (load) לפי כתובת, וכתיבה (store) לפי כתובת ונתון. התוכנית mem.c מקצה int, מדפיסה את הכתובת שלו, ומגדילה אותו כל שנייה:

int *p = malloc(sizeof(int));
printf("(%d) addr pointed to by p: %p\n", getpid(), p);
*p = 0;
while (1) { Spin(1); *p = *p + 1; printf("(%d) value of p: %d\n", getpid(), *p); }
prompt$ ./mem 0 & ./mem 100 &

(65) addr pointed to by p: 0x80052a0
(64) value of p: 1
(65) value of p: 101
(64) value of p: 2
(65) value of p: 102
שימו לב

אותה כתובת, ערכים שונים. הכתובת 0x80052a0 היא כתובת וירטואלית, לא כתובת ב-RAM. לכל תהליך יש מרחב כתובות וירטואלי משלו, ומערכת ההפעלה ממפה אותו לזיכרון הפיזי (ולפעמים לאחסון משני).

מקביליות

שני threads מגדילים מונה משותף loops פעמים כל אחד:

volatile int counter = 0;
void *worker(void *arg) {
    for (int i = 0; i < loops; i++) counter++;
    return NULL;
}

הסיבה: counter++ הוא שלוש פקודות מעבד ולא פעולה אטומית. אם יש החלפת הקשר באמצע, עדכון אחד "נבלע":

שלבThread 1Thread 2counter
1reg ← counter (0)0
2reg++ (1)0
3החלפת הקשרreg ← counter (0)0
4reg++ (1)0
5counter ← reg1
6counter ← reg1 ✗

שתי הגדלות, אבל המונה עלה רק ב-1. עם מעט איטרציות זה כמעט לא קורה; עם מיליונים זה קורה הרבה. עוד נחזור לזה בחלק המקביליות.

אחסון (Persistence)

זיכרון המערכת (DRAM) הוא נדיף – המידע הולך לאיבוד בכיבוי או בקריסה. לכן צריך חומרה (דיסק, SSD) ותוכנה – מערכת הקבצים – שמתרגמת "קבצים ותיקיות" של המשתמש לבלוקים בהתקן.

int fd = open(argv[1], O_WRONLY | O_CREAT, S_IRWXU);   // open (and create)
char buffer[20] = "hello world\n";
int rc = write(fd, buffer, strlen(buffer));            // write
close(fd);                                             // close

כתיבה לדיסק דורשת להחליט איפה יישב המידע ולשלוח בקשות I/O להתקן – וזה איטי. לכן מערכת ההפעלה בדרך כלל מעכבת כתיבות בתקווה לאגד כמה יחד.

קרנל, אירועים וקריאות מערכת

הקרנל
  • החלק המרכזי של מערכת ההפעלה, תמיד בזיכרון.
  • רץ בתגובה לאירועים – קריאת מערכת, לחיצת מקש, שעון.
  • הקרנל אינו תוכנית רצה. הוא קוד שמופעל כשיש אירוע.
  • לא כל מה שנראה כמו "מערכת ההפעלה" הוא קרנל: ה-shell של יוניקס, למשל, הוא אפליקציה רגילה.

אירוע (הזזת עכבר, מקש, תקשורת, חלוקה באפס, קריאת מערכת) קוטע את התוכנית הנוכחית ומריץ קוד קרנל. לכל סוג אירוע מוגדר בקרנל handler.

סוגמאפייןדוגמה
Interrupt (פסיקה)אסינכרוני – חיצוני לתוכניתלחיצת מקש; הקרנל שומר אותה ואפשר לבדוק אחר כך
Trap (מלכודת)סינכרוני – נגרם מהפקודה שרצה. נקרא גם exception / faultחלוקה באפס – הקרנל מסיים את התוכנית. לא בהכרח שגיאה: גם קריאת מערכת היא trap

קריאת מערכת (system call): תוכנית משתמש לא יכולה פשוט "לקפוץ" לקוד הקרנל. כשהיא רוצה לפתוח קובץ, להקצות זיכרון או לקרוא מהמקלדת, היא מבצעת trap מכוון – והמעבד עובר לקרנל באופן מבוקר.
