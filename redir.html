Chapter 6 · Redirection & Pipes

הפניות וצינורות

איך ה-shell מממש את > ו-| בלי שהתוכנית שרצה תדע בכלל: קבצים, file descriptors, dup2 ו-pipe. שאלות exec מהפרק הזה חוזרות כמעט בכל מבחן.

חזרה: exec – תוכנית אחרת באותו תהליך

execvp טוען לתהליך הנוכחי את קובץ הריצה של תוכנית אחרת: ה-Text, ה-Data, ה-Heap וה-Stack נדרסים, ו-main של התוכנית החדשה מתחיל לרוץ. לא נוצר תהליך חדש, ו-exec שהצליח לא חוזר.

מה נשמר אחרי exec
נשמרלא נשמר
מזהה התהליך – אותו PID ואותו הורהכל הזיכרון: קוד, משתנים, ערימה, מחסנית
הקבצים הפתוחים – כל ה-file descriptorsה-signal handlers – הקוד שלהם נדרס, ולכן הם חוזרים לברירת מחדל
סיגנלים שמוגדרים להתעלמות (SIG_IGN)

הקבצים הפתוחים נשמרים – וזה כל הסוד של הפניות: משנים את הקבצים הפתוחים אחרי fork ולפני exec, והתוכנית החדשה כותבת לאן שהפנינו בלי לדעת.

שאלות מבחינות על exec

בשלוש השאלות: כל קריאות המערכת מצליחות, לא נוצרים תהליכים אחרים במערכת, וכל תהליך חדש מקבל מזהה גדול ב-1 מהקודם. כל התשובות נבדקו בהרצה אמיתית.

24BA · מה ההמשך?

נתון הקוד של תוכנית בשם myexec:

int main()
{
    char* args[] = {"myexec", NULL};
    printf("PID: %d\n", getpid());
    execvp(args[0], args);
}

הריצו את התוכנית, ושורת הפלט הראשונה הייתה PID: 300. מה ההמשך?

פתרון

"PID: 300" שוב ושוב, עד שעוצרים את התוכנית. execvp מריץ שוב את main של myexec באותו תהליך, כך שזו בעצם לולאה אינסופית. לא נוצר אף תהליך חדש, ולכן ה-PID לא משתנה והתוכנית גם לא תקרוס בגלל ריבוי תהליכים.

בהרצה אמיתית: חמש השורות הראשונות היו אותו PID בדיוק.

24BB · מה הפלט?

נתון הקוד של תוכנית בשם execme:

int main()
{
    char* args[] = {"execme", NULL};
    if (!fork()) {
        execvp(args[0], args);
        printf("PID: %d\n", getpid());
    }
}

הריצו את התוכנית, והתהליך שנוצר קיבל את המזהה 300. מה הפלט?

פתרון

אין פלט בכלל. ה-printf נמצא אחרי execvp, והוא ירוץ רק אם exec נכשל – וכאן כל הקריאות מצליחות.

מה כן קורה: כל תהליך יוצר ילד ומסתיים, והילד מריץ את execme מההתחלה – וחוזר חלילה. זו שרשרת אינסופית של תהליכים (300, 301, 302…), אבל בכל רגע חיים לכל היותר שניים, ולכן המערכת לא קורסת מריבוי תהליכים. כל ילד נשאר יתום ומאומץ על ידי init.

בהרצה אמיתית (עם הגבלה ל-6 דורות): אפס שורות פלט, וכל ילד מהדור השני והלאה דיווח שההורה שלו הוא PID 1.

22BB · פלט אפשרי, ומספר התהליכים
int main() {
    int r1 = fork() || fork();
    if (r1) {
        char* args[3] = {"echo", "r1: TRUE", NULL};
        execvp(args[0], args);
        printf("r1: TRUE\n");
    } else {
        printf("r1: FALSE\n");
    }
    wait(NULL);

    int r2 = fork() && fork();
    if (r2) {
        char* args[3] = {"echo", "r2: TRUE", NULL};
        execvp(args[0], args);
    }
    else {
        printf("r2: FALSE\n");
    }
    if (r1 || r2)
        printf("END\n");
}

כתבו פלט אפשרי, וכמה תהליכים נוצרו. תזכורת: ב-&& וב-||, אם התוצאה כבר ידועה מהאופרנד הראשון, השני לא מבוצע.

אף תהליך לא מדפיס END: שני התהליכים היחידים שמגיעים לשורה האחרונה הם בני הנכד, ואצלם r1 ו-r2 שניהם 0. נוצרו 5 תהליכים בסך הכל (כולל המקורי).

בהרצה אמיתית של 200 פעמים: תמיד בדיוק 6 שורות האלה ובלי END. סדר השורות יכול להשתנות, כי התהליכים רצים במקביל.

פעולות על קבצים

ברמת מערכת ההפעלה קובץ פתוח מזוהה על ידי מספר שלם – file descriptor (FD). זה המקביל של FILE* בספריית C, אבל ברמה נמוכה יותר.

int open(const char* pathname, int flags, mode_t mode);
מחזיר
את ה-FD החדש – תמיד הקטן ביותר הפנוי – או -1 אם הפתיחה נכשלה.
flags
חובה בדיוק אחד מבין O_RDONLY, O_WRONLY, O_RDWR, ואפשר להוסיף עם |: O_CREAT (יצירה אם לא קיים), O_APPEND (כתיבה לסוף), O_TRUNC (מחיקת התוכן אם קיים).
mode
ההרשאות לקובץ חדש, במבנה RWXRWXRWX כמספר בינארי. לדוגמה 0644 הוא rw-r--r--.
ssize_t read(int fd, void* buf, size_t count); ssize_t write(int fd, void* buf, size_t count);
buf, count
לאן לקרוא / מאיפה לכתוב, וכמה בתים.
מחזיר
כמה בתים נקראו או נכתבו בפועל (יכול להיות פחות מ-count), -1 בשגיאה, ו-0 ב-read כשאין עוד מה לקרוא (EOF).
off_t lseek(int fd, off_t offset, int whence); int close(int fd);
whence
יחסית למה ה-offset: SEEK_SET (תחילת הקובץ), SEEK_CUR (המיקום הנוכחי), SEEK_END (סוף הקובץ).
מעבר לסוף
מותר לחרוג מסוף הקובץ. כתיבה שם "מרחיבה" את הקובץ, והרווח מתמלא באפסים.
בדקתי: כתיבה אחרי סוף הקובץ
int f = open("s.bin", O_WRONLY | O_CREAT | O_TRUNC, 0644);
write(f, "AB", 2);
lseek(f, 5, SEEK_END);   // 5 bytes past the end
write(f, "C", 1);
close(f);

התוכן בפועל (לפי od -c): A B \0 \0 \0 \0 \0 C – שמונה בתים, וחמישה אפסים באמצע.

הפניות ו-dup2

לכל תהליך יש טבלת file descriptors, ושלוש הכניסות הראשונות פתוחות מההתחלה:

FDשםתפקידמי משתמש
0stdinקלט סטנדרטיscanf
1stdoutפלט סטנדרטיprintf
2stderrדיווח שגיאותperror

printf לא יודע לאן הוא כותב – הוא פשוט כותב ל-FD 1. אם נגרום ל-FD 1 להצביע על קובץ, כל הפלט יגיע לקובץ.

int dup(int oldfd); int dup2(int oldfd, int newfd);
dup
משכפל את oldfd אל ה-FD הפנוי הקטן ביותר. אחרי השכפול שני המספרים מצביעים על אותו קובץ פתוח.
dup2
משכפל את oldfd בדיוק אל newfd, וסוגר את newfd קודם אם הוא היה בשימוש.
למה צריך
כשיש לנו כבר FD (למשל של pipe) ורוצים שהוא יהיה דווקא 0 או 1.

נסו בעצמכם. כל פעולה מקבלת את ה-FD כמו שמערכת ההפעלה הייתה נותנת:

בדקתי: dup אחרי close(1)
int f = open("x.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);  // 3
int a = dup(f);    // 4 – the lowest free FD
close(1);
int b = dup(f);    // 1 – now FD 1 is the lowest free
printf("to file\n");

בהרצה: open=3 dup=4 after close(1) dup=1, והשורה to file נכתבה לקובץ ולא למסך. זו הדרך ה"ישנה" להפניה – dup2 עושה את הסגירה וההעתקה בפעולה אחת.

כך עובד ה-shell

while (1) {
    char **args = read_user();        // read a command
    pid_t rc = fork();                // new process
    if (rc == 0) {
        /* set up process: redirections */
        execvp(args[0], args);        // run the program
    }
    else {
        if (!bg)                      // unless running in background (&)
            waitpid(rc, NULL, 0);
    }
}
ls >; out.txt – מה ה-shell עושה בפועל
pid_t rc = fork();
if (rc == 0) {
    int fd = open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) { perror("open"); exit(1); }
    dup2(fd, STDOUT_FILENO);   // FD 1 now points to out.txt
    close(fd);                 // the copy in FD 1 is enough
    char *args[] = { "ls", NULL };
    execvp(args[0], args);     // ls writes to FD 1 without knowing
    perror("execvp"); exit(1);
}
waitpid(rc, NULL, 0);

הרצתי בתיקייה עם a.c, b.c, c.txt: הקובץ out.txt הכיל את ארבעת השמות (כולל out.txt עצמו, כי הוא נוצר לפני ש-ls רץ), ושום דבר לא הודפס למסך.

תקשורת בין תהליכים: FIFO ו-pipe

אפשר לתקשר דרך קובץ רגיל, אבל זה מסורבל (מה אם קראנו לפני שנכתב? צריך סנכרון) ובזבזני (הנתונים נשמרים בדיסק בלי צורך).

מנגנוןאיך יוצריםמתי משתמשים
FIFO (named pipe)mkfifo(pathname, mode), או הפקודה mkfifo ב-shellבין תהליכים שאין ביניהם קשר. יש שם בתיקייה, אבל שום דבר לא נכתב לדיסק – הנתונים עוברים ב-buffer בזיכרון הקרנל. כל תוכנית שקוראת או כותבת לקובץ אפשר להפנות ל-FIFO.
pipe (unnamed pipe)pipe(int pipefd[2])בין תהליכים קשורים (pipe ואחריו fork). אותו מנגנון בלי קובץ. עליו מבוסס השרשור |.
pipe(fd)

fd[1] הוא הצד הכותב, fd[0] הוא הצד הקורא. מה שנכתב ל-fd[1] נקרא מ-fd[0], דרך buffer בזיכרון הקרנל.

מצבמה קורה
קריאה, ה-buffer ריקהקריאה חוסמת עד שנכתבים נתונים
קריאה, כל הצדדים הכותבים נסגרוקוראים את מה שנשאר, ואז EOF (read מחזיר 0)
כתיבה, ה-buffer מלאהכתיבה חוסמת עד שקוראים נתונים
כתיבה, כל הצדדים הקוראים נסגרוהתהליך מקבל SIGPIPE

אחרי fork לשני התהליכים יש את שני הצדדים. התקשורת חד-כיוונית (כדי להימנע מבעיות סנכרון): כל תהליך סוגר את הצד שהוא לא משתמש בו. לתקשורת דו-כיוונית משתמשים בשני צינורות.

ls | wc -l – מה ה-shell עושה בפועל
int fd[2];
pipe(fd);                          // fd[0] = read end, fd[1] = write end
if (fork() == 0) {                 // first child: ls
    dup2(fd[1], STDOUT_FILENO);
    close(fd[0]); close(fd[1]);
    execlp("ls", "ls", NULL);
    perror("ls"); exit(1);
}
if (fork() == 0) {                 // second child: wc -l
    dup2(fd[0], STDIN_FILENO);
    close(fd[0]); close(fd[1]);
    execlp("wc", "wc", "-l", NULL);
    perror("wc"); exit(1);
}
close(fd[0]); close(fd[1]);        // parent must close too
while (wait(NULL) > 0);

בהרצה התקבל 4, בדיוק כמו ls | wc -l ב-shell באותה תיקייה.

המלכודת: לשכוח לסגור צד כותב

wc מסיים רק כשהוא מקבל EOF, וזה קורה רק כשכל הצדדים הכותבים של הצינור סגורים – גם זה שאצל ההורה. מחקתי מהקוד למעלה את השורה close(fd[0]); close(fd[1]); של ההורה והרצתי: התוכנית נתקעה ונעצרה רק אחרי timeout של שתי שניות.

תרגיל: הפניה ושרשור

תרגול נוסף (הרצאה + תרגול 3)

כתבו תוכנית ש:

  • יוצרת תהליך חדש.
  • בתהליך המקורי מבצעת הפניית פלט לפי ארגומנט 1 (שם קובץ).
  • בתהליך החדש מבצעת הפניית קלט לפי ארגומנט 2 (שם קובץ).
  • משרשרת בין התהליכים, כך שהפלט של התהליך החדש מופנה לקלט של התהליך המקורי – באמצעות pipe. לזכור לסגור את כל הצדדים שלא בשימוש.
  • מריצה בתהליך החדש את התוכנית לפי הארגומנט השלישי והלאה (אפשר להניח שאין סימנים מיוחדים).
  • מדפיסה בתהליך המקורי את כל הקלט שמתקבל.
  • בודקת שגיאות לאורך כל הדרך.
פתרון 
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/wait.h>

/* usage: ./redir <out-file> <in-file> <prog> [args...] */
int main(int argc, char *argv[]) {
    if (argc < 4) { fprintf(stderr, "usage: %s out in prog [args]\n", argv[0]); exit(1); }
    int fd[2];
    if (pipe(fd) == -1) { perror("pipe"); exit(1); }

    pid_t rc = fork();
    if (rc == -1) { perror("fork"); exit(1); }

    if (rc == 0) {                                   /* child: in-file -> prog -> pipe */
        int in = open(argv[2], O_RDONLY);
        if (in == -1) { perror("open input"); exit(1); }
        if (dup2(in, STDIN_FILENO) == -1) { perror("dup2"); exit(1); }
        if (dup2(fd[1], STDOUT_FILENO) == -1) { perror("dup2"); exit(1); }
        close(in); close(fd[0]); close(fd[1]);       /* close every unused end */
        execvp(argv[3], &argv[3]);
        perror("execvp");                            /* reached only if exec failed */
        exit(1);
    }

    /* parent: pipe -> stdin, stdout -> out-file */
    int out = open(argv[1], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (out == -1) { perror("open output"); exit(1); }
    if (dup2(fd[0], STDIN_FILENO) == -1) { perror("dup2"); exit(1); }
    if (dup2(out, STDOUT_FILENO) == -1) { perror("dup2"); exit(1); }
    close(out); close(fd[0]); close(fd[1]);          /* must close write end, or read never sees EOF */

    char buf[256];
    ssize_t n;
    while ((n = read(STDIN_FILENO, buf, sizeof buf)) > 0)
        if (write(STDOUT_FILENO, buf, n) != n) { perror("write"); exit(1); }
    if (n == -1) { perror("read"); exit(1); }
    int status;
    if (waitpid(rc, &status, 0) == -1) { perror("waitpid"); exit(1); }
    if (WIFEXITED(status) && WEXITSTATUS(status) != 0) {
        fprintf(stderr, "child failed with code %d\n", WEXITSTATUS(status));
        exit(1);
    }
    return 0;
}

בדיקה בהרצה:

  • ./redir out.txt in.txt sort כש-in.txt מכיל banana, apple, cherry: ב-out.txt התקבל apple, banana, cherry.
  • ./redir out2.txt in.txt wc -l: התקבל 3.
  • קובץ קלט שלא קיים: התוכנית מדפיסה את השגיאה והקוד שלה הוא 1:
    open input: No such file or directory
child failed with code 1

שתי נקודות חשובות: ההורה סוגר את fd[1] לפני הקריאה – אחרת read לא יקבל אף פעם EOF והתוכנית תיתקע. וההורה בודק את סטטוס היציאה של הילד עם WEXITSTATUS, כדי לדווח אם הילד נכשל.

סיכום פרק 6
  • exec שומר PID, קבצים פתוחים וסיגנלים מסוג SIG_IGN; כל השאר נדרס. exec שהצליח לא חוזר.
  • open ו-dup מחזירים תמיד את ה-FD הפנוי הקטן ביותר; -1 הוא שגיאה.
  • הפניה = fork, open, dup2 לתוך 0 או 1, close, exec.
  • pipe: fd[1] כותב, fd[0] קורא; קריאה חוסמת כשריק, EOF רק כשכל הכותבים סגורים, SIGPIPE כשאין קוראים.
  • לסגור כל צד שלא בשימוש – בכל תהליך, כולל ההורה.
