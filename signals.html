Chapter 5 · Zombies & Signals

זומבים וסיגנלים

התרגול השני: שאלות fork בסגנון מבחן, למה printf מודפס פעמיים, מה זה זומבי ואיך סיגנלים עוזרים להיפטר ממנו.

שיטה: ספירת תהליכים ופלטים

איך פותרים
  1. מציירים עץ: כל fork מפצל ענף לשניים – הורה (ערך החזרה > 0, "אמת") וילד (0, "שקר").
  2. עוקבים אחרי כל ענף בנפרד דרך התנאים: if (fork()) נכנס רק בהורה, if (!fork()) רק בילד.
  3. מספר ההדפסות של שורה = מספר התהליכים שמגיעים אליה.
  4. n קריאות fork ברצף בלי תנאים נותנות 2^n תהליכים.
  5. באופרטור && – אם האופרנד הראשון שקר (0, כלומר בילד), השני לא מבוצע.

כל התשובות כאן נבדקו בהרצה אמיתית של הקוד (עם setbuf(stdout, NULL)).

תרגיל 1 · שלושה fork ברצף
fork(); fork(); fork();
printf("hello there\n");
פתרון

8 שורות.

2³ = 8

כל fork מכפיל את מספר התהליכים.

תרגיל 2 · fork בתוך if
if (fork()) { fork(); }
printf("hello there\n");
פתרון

3 שורות. הילד הראשון מדלג על הבלוק; ההורה נכנס ויוצר עוד ילד. סך הכל 3 תהליכים.

תרגיל 3 · כמה תהליכים?
if (fork()) { fork(); fork(); }
פתרון

5 תהליכים. הילד הראשון לא נכנס. ההורה נכנס ומבצע שני fork – הופך ל-4 תהליכים בענף שלו.

1 + 2² = 5
תרגיל 4 · if (!fork())
if (!fork()) { fork(); }
fork();
פתרון

6 תהליכים. אחרי ה-if יש 3 (הורה, ילד, והנכד שהילד יצר), וה-fork האחרון מכפיל.

3 × 2 = 6
תרגיל 5 · כמה תהליכים?
fork();
if (fork()) { fork(); }
fork();
פתרון

12 תהליכים. אחרי השורה הראשונה 2. כל אחד מהם הופך ל-3 בגלל ה-if (כמו בתרגיל 2), וה-fork האחרון מכפיל.

2 × 3 × 2 = 12
תרגיל 6 · fork אחרי if
int pid = fork();
if (pid)
    fork();
fork();
printf("hello there\n");

כמה פעמים מודפס hello there?

פתרון

6 פעמים. אחרי השורה הראשונה יש 2 תהליכים. רק ההורה (pid שונה מ-0) נכנס ל-if ויוצר עוד אחד – עכשיו 3. ה-fork האחרון מכפיל את כולם.

(1 + 2) × 2 = 6

בדקתי בהרצה: 6 שורות.

שאלות מבחינות

SB20 · מה יכול להיות הפלט?
int i = 0;
if (fork()) {
    ++i;
    fork();
}
else if (fork())
    ++i;
printf("%d", i);
פתרון

4 תהליכים: ההורה מגדיל ל-1 ומשכפל את עצמו – שתי הדפסות של 1. הילד (i=0) נכנס ל-else ומבצע fork: הוא עצמו (ההורה של הנכד) מגדיל ל-1, והנכד נשאר 0.

התשובה: שלוש ספרות 1 ואחת 0, בכל סדר. בהרצה של 200 פעמים ראיתי 1110, 1101 ו-1011.

SA20 · מה יכול להיות הפלט?
fork();
if (fork() == 0) {
    printf("B");
} else {
    wait(NULL);
    printf("A");
}
פתרון

אחרי השורה הראשונה יש P ו-P2. כל אחד יוצר ילד שמדפיס B, ואז מחכה ומדפיס A. סך הכל שני B ושני A.

הפלטים האפשריים: BBAA, BABA, BAAB.

המלכודת: BAAB

ל-P יש שני ילדים: P2, וגם הילד שמדפיס B. הפונקציה wait חוזרת כשילד כלשהו מסתיים, ולכן ייתכן הסדר הזה:

  1. הילד של P2 מדפיס B.
  2. P2 מדפיס A ומסתיים.
  3. ה-wait של P חוזר בגלל ש-P2 הסתיים, ו-P מדפיס A.
  4. רק עכשיו הילד של P מדפיס B.

זה נדיר (פעם אחת מתוך 500 הרצות) אבל אפשרי. מה שבלתי אפשרי: פלט שמתחיל ב-A.

AA24 · מה הפלט?
char *str = "hello";
if (fork() && fork()) {
    wait(NULL);
    printf("1: %s\n", str);
    wait(NULL);
    printf("1: %s\n", str);
} else {
    wait(NULL);
    printf("0: %s\n", str);
    str = "goodbye";
    wait(NULL);
    printf("0: %s\n", str);
}
פתרון

3 תהליכים. ההורה: שני ה-fork מחזירים ערך חיובי, נכנס ל-if. הילד הראשון: ה-fork הראשון החזיר 0, ולכן השני לא מבוצע – נכנס ל-else. הילד השני: ה-fork השני החזיר לו 0 – else.

לשני הילדים אין ילדים, אז ה-wait שלהם חוזר מיד עם -1. כל ילד מדפיס:

0: hello
0: goodbye

ההורה מדפיס 1: hello פעמיים – השינוי של str קרה בעותקים של הילדים.

אילוצי סדר:

  • אצל כל ילד השורה עם hello מופיעה לפני השורה עם goodbye.
  • השורה הראשונה של ההורה מופיעה רק אחרי שאחד הילדים סיים את שתי השורות שלו.
  • השורה השנייה של ההורה היא תמיד האחרונה. סך הכל 6 שורות.

הרצה בפועל: באפר ו-setbuf

printf("Good afternoon");
fork();
printf(", good evening");
fork();
printf(" and good night\n");

באופן מפתיע מודפס 4 פעמים המשפט המלא – כולל "Good afternoon" שנכתב לפני כל fork. הסיבה: printf כותב לבאפר בזיכרון התהליך, והוא נשלח למסך רק בשורה חדשה, ב-fflush או ביציאה. fork מעתיק את הזיכרון, כולל הבאפר שעוד לא נשלח.

גרסהמה מודפס
בלי כלוםהמשפט המלא × 4
fflush(stdout) אחרי כל printfGood afternoon × 1, good evening × 2, and good night × 4
setbuf(stdout, NULL) בתחילת התוכניתכמו fflush – כל printf נשלח מיד
כלל הקורס

בקוד שלכם תמיד משתמשים ב-setbuf(stdout, NULL), ובשאלות מבחן תמיד מניחים שהוא קיים.

יתומים וזומבים

printf("PID: %d\n", getpid());
int rc = fork();
if (rc < 0)       { fprintf(stderr, "fork failed\n"); exit(1); }
else if (rc == 0) printf("Child %d of parent %d\n", getpid(), getppid());
else              printf("Parent %d of child %d\n", getpid(), rc);

לפעמים הילד מדפיס "of parent 1". זה קורה כשההורה מסתיים לפני הילד. הילד נעשה יתום ומאומץ על ידי init (PID 1).

זומבי

המקרה ההפוך: הילד מסתיים לפני ההורה. הוא לא נמחק – הוא נשאר בטבלת התהליכים כזומבי, כי ההורה עלול לרצות את סטטוס היציאה שלו. הוא נשאר עד שנאסף.

  • wait / waitpid אוספים זומבים.
  • כשההורה מסתיים, init מאמץ ואוסף את הזומבים שלו.

זה לא מספיק: תהליך שמריץ ילדים ברקע, לא רוצה לחכות להם ולא מסתיים (שרת, shell) – יצבור זומבים. הפתרון: סיגנלים.

סיגנלים

סיגנל הוא מנגנון להעברת הודעות לתהליכים – מתהליך לתהליך, או ממערכת ההפעלה לתהליך. נקראים גם "פסיקות תוכנה", אבל לא להתבלבל:

מונחלמי ההודעה
סיגנלאל תהליך
פסיקה (interrupt)אל המעבד / הקרנל

יש 31 סיגנלים סטנדרטיים (ממוספרים 1–31, קבועים שמתחילים ב-SIG), ועוד נוספים.

סיגנלמתיאפשר לתפוס?
SIGINTCtrl+Cכן
SIGCHLDהקרנל שולח להורה כשילד מסתייםכן
SIGKILLהריגה מיידיתלא – מטופל ע"י הקרנל
SIGSTOPהשהיהלא – מטופל ע"י הקרנל
int kill(pid_t pid, int sig);
מה
שולחת את הסיגנל sig לתהליך pid. השם מטעה – אפשר לשלוח כל סיגנל, לא רק להרוג.
int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact);
מה
משנה את הטיפול בסוג סיגנל. לכל סיגנל יש טיפול ברירת מחדל, ואפשר להחליף אותו ב-signal handler – פונקציה של התהליך שמקבלת את מספר הסיגנל.
act
הטיפול החדש: sa_handler הוא פונקציה, SIG_DFL (ברירת מחדל) או SIG_IGN (התעלמות).
oldact
פרמטר פלט: לכאן נכתב הטיפול הקודם. שימושי כדי לשחזר או להחליף.
מניעת זומבים עם SIGCHLD
void on_child(int sig) {
    while (waitpid(-1, NULL, WNOHANG) > 0)   // reap all zombies, without blocking
        ;
}
...
struct sigaction sa = {0};
sa.sa_handler = on_child;
sigaction(SIGCHLD, &sa, NULL);

שני פרטים חשובים: WNOHANG כדי שה-handler לא ייחסם, ולולאה – כי סיגנלים מאותו סוג לא נספרים. אם שני ילדים מתו כמעט יחד, ייתכן שיגיע SIGCHLD אחד בלבד.

ניהול שגיאות

כמעט כל קריאת מערכת מחזירה int, ו-1 תמיד מציין כישלון. הסיבה נשמרת במשתנה הגלובלי errno, שמתעדכן אחרי כל קריאת מערכת – לכן בודקים אותו מיד.

if (fork() == -1) {
    perror("fork");                          // fork: Resource temporarily unavailable
    fprintf(stderr, "%s\n", strerror(errno)); // same text, as a string
}

תרגיל: טיפול בסיגנלים

תרגול נוסף (שקף 24)

כתבו תוכנית ש:

  • מטפלת ב-SIGINT וב-SIGCHLD באותה פונקציה (רמז: הארגומנט של ה-handler).
  • בכל Ctrl+C מחליפה בין טיפול בזומבים לבין ברירת מחדל (רמז: הארגומנט השלישי של sigaction).
  • יוצרת ילד חדש (שרץ 5 שניות ומסיים) בכל SIGCHLD.
  • בכל SIGINT: אם יש ילד (ככל שההורה יודע) – הורגת אותו עם SIGKILL; אחרת יוצרת ילד חדש (רמז: משתנה גלובלי).
  • מדפיסה כל שלב.
פתרון 
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>
#include <sys/wait.h>

static volatile pid_t child = 0;   /* current child, as far as the parent knows */
static struct sigaction other;      /* the inactive SIGCHLD handler, for toggling */
static int reaping = 1;             /* 1 = reap zombies, 0 = default */

static void spawn(void) {
    pid_t p = fork();
    if (p == 0) { sleep(5); _exit(0); }   /* child: runs 5 seconds, then exits */
    child = p;
    printf("[parent] created child %d\n", p);
}

static void handler(int sig) {
    if (sig == SIGCHLD) {
        pid_t p;
        while ((p = waitpid(-1, NULL, WNOHANG)) > 0) {
            printf("[parent] reaped zombie %d\n", p);
            if (p == child) child = 0;
        }
        spawn();
    } else if (sig == SIGINT) {
        if (child) {
            printf("[parent] SIGKILL -> %d\n", child);
            kill(child, SIGKILL);
            child = 0;
        } else {
            spawn();
        }
        struct sigaction cur;
        sigaction(SIGCHLD, &other, &cur);  /* swap in, save the previous one */
        other = cur;
        reaping = !reaping;
        printf("[parent] SIGCHLD mode: %s\n", reaping ? "reap zombies" : "default");
    }
}

int main(void) {
    setbuf(stdout, NULL);
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sigaction(SIGINT, &sa, NULL);
    sigaction(SIGCHLD, &sa, NULL);
    other.sa_handler = SIG_DFL;          /* the mode we switch to the first time */
    sigemptyset(&other.sa_mask);
    spawn();
    while (1) pause();
}

הרעיון המרכזי: other מחזיק תמיד את הטיפול שלא פעיל כרגע. קריאה אחת ל-sigaction(SIGCHLD, &other, &cur) מתקינה אותו ומחזירה ב-cur את הפעיל הקודם – וכך כל Ctrl+C מחליף בין השניים.

פלט מהרצה אמיתית (ילד ראשון, אחרי 6 שניות Ctrl+C, ושוב Ctrl+C):

[parent] created child 3184
[parent] reaped zombie 3184
[parent] created child 3186
[parent] SIGKILL -> 3186
[parent] SIGCHLD mode: default
[parent] created child 3188
[parent] SIGCHLD mode: reap zombies

במצב "default" ילד שמת נשאר זומבי ולא נוצר ילד חדש. הזומבי ייאסף בפעם הבאה שה-handler ירוץ במצב איסוף, כי waitpid(-1, ...) אוסף כל ילד. הערה: הפונקציה printf אינה בטוחה לשימוש בתוך handler (היא לא async-signal-safe), אבל בתרגיל הזה מקובל להשתמש בה לצורך הדגמה.

סיכום פרק 5
  • ספירה: מציירים עץ, עוקבים אחרי ערך ההחזרה בכל ענף, זוכרים קיצור של &&.
  • wait מחכה לילד כלשהו – מקור למלכודות סדר.
  • באפר לא שנשלח משוכפל ב-fork; תמיד setbuf(stdout, NULL).
  • הורה מת קודם ← יתום, מאומץ ע"י init. ילד מת קודם ← זומבי עד שנאסף.
  • SIGCHLD + waitpid(-1, NULL, WNOHANG) בלולאה = אין זומבים.
  • SIGKILL ו-SIGSTOP אי אפשר לתפוס. -1 = כישלון, הסיבה ב-errno.
